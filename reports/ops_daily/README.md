# Daily ops reports (synced Oracle → Mac)

Generated by **`scripts/generate_daily_ops_report.py`** on the **VM** (where `data/` and `logs/` exist).

## Why this folder

- **`data/`** is gitignored and excluded from `sync_pull_from_oracle.sh`, so your Mac clone normally **does not** get `pnl_ledger.jsonl` or screening meta.
- Reports here live under **`reports/`**, so a normal **pull from Oracle** brings **JSON + Markdown** snapshots into Cursor for review (including AI-assisted review).

## Generate on Oracle

```bash
cd /home/ubuntu/trading-bot
./venv/bin/python3 scripts/generate_daily_ops_report.py
```

Optional: **today’s label** (UTC) is default; override with `--utc-day 2026-03-23`.

Each run also writes **`LATEST.md`** and **`LATEST.json`** (copies of that run) so you can always open the same paths for evening review with Cursor.

## Pull to Mac (then open in Cursor)

```bash
./scripts/sync_pull_from_oracle.sh ubuntu@YOUR_ORACLE_IP
ls reports/ops_daily/
```

## Schedule (cron)

Example: every day **22:05 UTC**:

```cron
5 22 * * * cd /home/ubuntu/trading-bot && ./venv/bin/python3 scripts/generate_daily_ops_report.py >> logs/daily_ops_report.log 2>&1
```

## Privacy

Reports contain **tickers, PnL, order IDs, log lines**. They are **gitignored** (`reports/ops_daily/*.json` and `*.md`). Do not commit them to a public repo.

See **`docs/DAILY_OPS_REVIEW.md`** for the full workflow.
